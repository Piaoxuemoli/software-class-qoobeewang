# 项目简介：DataBackup 数据备份软件

## 1. 背景

《软件开发综合实验》（电子科技大学计算机专业第七学期实践必修课）要求以小组为单位，按面向对象软件工程方法完成一款**数据备份软件**，覆盖需求分析 → 系统设计 → 编码实现 → 软件测试全生命周期。最终成果是一款基本可用的软件 + 规范的文档。课程原始要求与评分细则见 `course-requirements.md`。

小组：**组长王科瑾，单人组，无组员**。

本项目**使用 AI 辅助开发**：编码 agent 承担大部分编码、测试与文档起草，组长负责需求与方向、设计决策、验收和现场答辩。实验报告第七章"AI 开发工具使用总结"的截图由组长在项目最后统一整理。

## 2. 目标

- 难度分顶格：基础 40 + 选定扩展 85（理论 125，封顶 110），留 15 分余量抵御"第三方库减半"等扣分风险。
- 完成分 ≥ 91：文档 50 分（需求 10 / 设计 20 / 测试 20）写规范，AI 证书 10 分拿满，源码质量、答辩、演示到位。
- 小组得分 = 完成分 × 难度分 ÷ 100，目标封顶 100。

## 3. 功能清单（需求编号，全仓库统一引用）

| 编号 | 功能 | 说明 | 计分项 |
|---|---|---|---|
| FR-01 | 数据备份 | 将源目录树备份为一个备份文件，存入备份仓库 | 基础 40 |
| FR-02 | 数据还原 | 将备份文件还原到指定目录，恢复目录树 | 基础 |
| FR-03 | 文件类型支持 | 普通文件、目录、软链接、硬链接、命名管道（FIFO）、字符设备、块设备、套接字 | 扩展 10 |
| FR-04 | 元数据支持 | 权限位、属主/属组（uid/gid）、访问/修改时间；还原时恢复 | 扩展 10 |
| FR-05 | 过滤：路径 | 选择源目录，排除指定子目录 | 扩展 5 |
| FR-06 | 过滤：类型 | 按文件类型（`- d l c b s p`）筛选 | 扩展 5 |
| FR-07 | 过滤：名字 | 按正则排除文件名 | 扩展 5 |
| FR-08 | 过滤：时间 | 按修改时间 / 创建（状态变更）时间区间筛选 | 扩展 5 |
| FR-09 | 过滤：尺寸 | 按文件大小区间筛选 | 扩展 5 |
| FR-10 | 过滤：用户/组 | 排除指定属主或属组的文件（参考界面有，新版评分未列，低成本附带） | 旧版 3 |
| FR-11 | 打包解包 | 自研 MyPack 归档格式（仿 tar：512 字节头记录 + 数据块） | 扩展 10 |
| FR-12 | 压缩解压 | 自研 Huffman 编码 | 扩展 10 |
| FR-13 | 加密解密 | 用户口令 → PBKDF2-HMAC-SHA256 派生密钥 → AES-256-CBC 加密 + HMAC 校验（全部手写） | 扩展 10 |
| FR-14 | 备份管理 | 列出、查看、删除备份仓库中的备份 | 支撑 |
| FR-15 | 设置 | 配置备份仓库路径等 | 支撑 |
| FR-16 | 图形客户端 | Electron 桌面客户端：备份 / 管理备份数据 / 备份设置 三个页面 | 扩展 10 |
| FR-17 | 安全与健壮性 | 完整性校验、错误口令识别、还原目录须为空、拒绝路径穿越、错误输入友好提示 | 软件考察项 |
| FR-18 | 进度与日志 | 后端以 JSON Lines 输出进度/日志/结果，客户端实时展示 | 易用性 |

备选（时间富余再做，不进入主计划）：S-1 LZ77 压缩、S-2 DES 加密、S-3 tar 格式兼容、S-4 定时备份。

明确不做：实时备份、网络备份（性价比低、需要服务器）。

## 4. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | **Go**（仅标准库，零第三方模块） | 课程允许的语言之一（课件列出 `go test` / `-bench` / `-cover` 工具链）；`go build` 一条命令出静态二进制，没有 C++ 的构建复杂度，代码好读；标准库 `syscall` 覆盖 `lstat/mkfifo/mknod/lchown/link/symlink/utimes`；测试、基准、覆盖率、race 检测、fuzz、pprof 全部内置 |
| 后端接口 | CLI 子命令 + `--json` 输出 JSON Lines | 后端可独立使用和测试；客户端通过子进程调用，边界清晰；协议见 `../architecture/cli-contract.md` |
| 客户端 | **Electron + React + TypeScript**（electron-vite 构建，electron-builder 打包 AppImage/deb）；界面 Tailwind v4 + shadcn/ui + React Bits，Grok 式纯黑单色风格，无边框自绘外框 | 课程允许界面用脚本语言；Web 技术做界面效率最高；打包后后端二进制随客户端一起分发（同 Kopia/KopiaUI 模式）。规范见 `../client/ui-design.md`、`../client/interaction.md` |
| 测试 | 后端 `go test`（单元/集成/fuzz/bench）+ testscript（CLI 黑盒，仅测试依赖）；客户端 Vitest + Playwright（交互 + 截图对比） | 对应课程测试要求（≥2 种测试类型、≥15 个用例）；方案参考 restic 与 Go 官方，见 `../research/2026-10-调研报告.md` |
| 文档 | Markdown + PlantUML；项目完成后一次性经 pandoc → LibreOffice 生成 PDF | 开发期只维护 Markdown，PDF 作为最终备份与提交件 |
| CI/CD | GitHub Actions（ubuntu-22.04） | PR 门禁 + 打 tag 自动发布 |

为什么不用 C#：Linux 下的 FIFO/设备文件/lchown 等需要 P/Invoke 或第三方包（Mono.Posix），反而违背"少依赖"。为什么不用 C++：构建与内存管理复杂度高，作者无法独立读懂和答辩。

## 5. 运行与开发环境

| 环境 | 用途 | 说明 |
|---|---|---|
| Windows 主机 | 编辑代码、git、运行 Docker Desktop | 不直接编译运行后端 |
| **Docker 开发镜像**（`docker/dev.Dockerfile`，Ubuntu 22.04） | 构建、测试、门禁（与 CI 一致） | `bash scripts/docker.sh check`；也可用 VSCode "Reopen in Container"。对应课程"组内开发环境统一：容器镜像" |
| **WSL2 Ubuntu + WSLg** | 演示与手工测试 | Electron 窗口直接显示在 Windows 桌面；在 WSL 的 ext4 文件系统上验证特殊文件和属主；`perf` 等性能证据也在这里采集 |
| GitHub Actions | CI 与 Release | 同一份 `scripts/install-deps.sh` 安装工具链 |
| 云服务器 | **不需要** | 不做网络备份 |
