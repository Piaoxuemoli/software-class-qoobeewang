# 课程要求基线

> 本文是需求的最终依据，整理自课程课件（第 0~6 次课）、实验指导书 1~4、官方《小组提交文档-实验报告模板》以及课程群记录。原始资料只在作者本地 `course/` 目录，不入库。括号内为出处页码。⚠️ 表示资料间存在矛盾或仍需向老师确认。

## 1. 课程目标与项目范围（课件0 p2-p4）

- 以小组（≤3 人）为单位"独立"实现一款**数据备份软件**，走完需求分析、系统设计、编码实现、软件测试全流程，基于面向对象软件工程方法学推进。
- 成果 = 一款基本可用的软件 + 对应文档。软件重点考察**正确性、易用性、健壮性**；文档重点考察**规范性、一致性、可读性**。
- 鼓励使用现代化工具：项目管理（Teambition 或类似）、UML 建模（StarUML）、IDE（VSCode/make/gdb）、版本控制（git + GitHub/Gitee）、代码检测（cpplint）、测试（gtest/valgrind/gprof/perf）。本项目选用 Go，对应工具见 §7。

## 2. 评分规则

### 2.1 总公式（课件0 p6）

```
若 考勤 ≥ 8/10 次：
  项目难度分 = 基础分 + 扩展分                      （≤110）
  项目完成分 = 需求分析说明书 10 + 系统设计文档 20 + 软件测试报告 20
             + AI 训练证书 10 + 源码质量 10 + 项目答辩 10 + 项目演示 20   （满分 110）
  小组得分 = 项目完成分 × 项目难度分 ÷ 100
  组长得分 = 小组得分（≤100）；组员得分 = 小组得分 − 5（≤100）
```

⚠️ 考勤不足 8 次时如何计分课件未写，需向老师确认。

基础要求（40 分）：数据备份（目录树中的文件数据保存到指定位置）+ 数据还原（恢复到指定位置）。

### 2.3 限制规则（课件0 p5）

- 操作系统：Linux / Windows / MacOS 任选。本项目：Linux。
- 开发语言：C / C++ / C# / Java / Go。**用户界面可用脚本语言；若后台逻辑也用脚本语言，基础分只记 10 分。** 本项目：后端 Go，界面 TypeScript。
- **对所有扩展功能，如使用第三方库/程序/代码"直接"实现，该功能扩展分记 50%。** 本项目：打包、压缩、加密、遍历、过滤、元数据全部自研；由 `scripts/check-imports.sh` 强制。⚠️ 客户端界面框架（Electron/React）是否会被认定为"直接实现"需确认；即便 GUI 减半，难度分仍有余量封顶。

### 5.1 需求分析说明书（模板大纲）

1 任务概述（1.1 引言；1.2 综合描述：产品的状况 / 产品的功能 / 用户类和特性；1.3 运行环境：硬件、操作系统、内存、硬盘、网络）→ 2 功能需求（2.1 功能划分；2.2 系统用例：每个用例 = **用例图 + 用例描述表**）→ 3 外部接口需求（用户界面 / 硬件接口 / 软件接口）→ 4 其它非功能需求（性能 / 安全性 / 软件质量属性）→ 5 项目规划（5.1 人员分工表；5.2 项目总体规划：**甘特图**及说明）。

## 6. 功能与技术要点

### 6.1 参考界面（课件5 p7-p16，窗口标题 "Data Backup"，3 个 Tab）

- **备份**：数据路径 + 选择路径；筛选子页 6 个：
  - 文件类型：复选 `-` 普通文件、`d` 目录、`l` 符号链接、`c` 字符设备、`b` 块设备、`s` 套接字、`p` 命名管道、all 全部；
  - 时间：创建时间区间、修改时间区间（各自可勾选启用）；
  - 文件大小：最小~最大 bytes；
  - 排除用户（组）：排除用户列表、排除用户组列表，可添加；
  - 排除文件名称：正则（示例 `^.*haha.?doc$`）；
  - 排除目录：目录列表，可添加。
  - 下方：打包算法（MyPack / tar）、压缩（Haff / LZ77）、加密（AES / DES + key 输入框）、"备份"按钮。
- **管理备份数据**：备份列表表格（文件名 / 文件大小 / 备份时间），选择文件 / 删除 / 刷新；备份文件、还原路径 + 选择路径、"还原"按钮；还原加密备份时弹出"请输入密码"对话框。
- **备份设置**：数据备份路径 + 选择路径 + "修改路径"。

### 6.2 备份正确性五要素（课件6 p19）

文件类型、文件路径、文件数据、文件元数据（属主/权限/时间）、文件链接方式（软/硬）。还原结果须在这五方面与源一致——这就是 e2e 测试的比较基准。

### 6.3 Unix 文件类型（课件6 p5-p17）

普通文件 `-`、目录 `d`、软链接 `l`、字符设备 `c`、块设备 `b`、套接字 `s`、命名管道 `p`；硬链接是指向同一 inode 的多个目录项（不能跨文件系统、不能链接目录）。涉及 API：`stat/lstat`（lstat 不跟随软链接）、`opendir/readdir`、`open/read/write`、`chmod/chown/utime`、`link/symlink`、`mkdir/mkfifo/unlink` 等。

### 6.4 打包实现提示（课件6 p36-p42）

- 仿 tar：文件对象线性排列，每个对象 = 512 字节头记录 + 数据（补齐到 512 的倍数）；归档末尾两个全零块。
- 头记录字段：name[100]、mode[8]、uid[8]、gid[8]、size[12]、mtime[12]、check[8]、link 类型、link_name[100]；UStar 扩展：type、ustar 标识、owner[32]、group[32]、major[8]、minor[8]、prefix[155]。类型码：`0` 普通、`1` 硬链接、`2` 软链接、`3` 字符设备、`4` 块设备、`5` 目录、`6` FIFO。
- 遍历与打包解耦（遍历输出文件列表，打包消费列表）；列表采用**先序遍历**；硬链接保持链接关系、软链接只存链接本身、用 lstat 防目录软链接死循环；切换到源目录后用相对路径；遍历中完成过滤。
- 打包前检查源/目的路径存在且可访问；解包前校验头记录、**目的目录必须为空**；文件名超长用多个头块；恢复元数据。

### 6.5 测试要求（课件3 p38）

- 推荐白盒单元测试，测试代码留在源码中。
- 推荐在开发中使用内存/性能分析工具，并在报告中体现。
- 报告至少包含 **2 种以上测试类型**（单元、集成、性能、稳定性等）和 **15 个以上测试用例**。
- 白盒测试方法：语句/判定/条件/判定-条件/条件组合/路径覆盖（课件3 p30-p31）。
