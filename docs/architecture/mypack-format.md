# MyPack 归档格式（版本 1）

MyPack 是本项目自研的归档格式（FR-11），由 `backend/internal/pack` 实现。设计仿 tar/UStar（课件6 p36-p42）：文件对象线性排列，每个对象 = 512 字节头记录 + 数据（补齐到 512 的倍数），长文件名使用多个头块，归档以两个全零块结尾。与 tar 的差别是：字段为定长**小端二进制**而非 ASCII 八进制；时间精确到纳秒；校验和用 CRC-32；对路径安全做强制校验。

MyPack 只负责"条目序列"，不含压缩、加密、统计与完整性校验值——这些由外层 `.dbk` 容器负责（见 `overview.md` ADR-012）。格式变化必须同步本文、`pack` 包常量与 `backend/internal/pack/testdata/*.golden`，并在提交 footer 写 `BREAKING CHANGE:`。

## 1. 总体结构

```
归档   = { 条目 } 结尾
条目   = 头块 { 扩展块 } [ 数据块… ]
结尾   = 零块 零块              （两个 512 字节全零块）
```

- **头块**（512 字节）：固定字段 + 内联名字区（408 字节）。
- **扩展块**（每块 512 字节，个数由头块 `extBlocks` 给出）：名字区放不下时，路径与链接目标的剩余部分接着写在扩展块里。
- **数据块**：只有普通文件（非硬链接）有数据，长度 `size` 字节，末尾以 0 补齐到 512 的倍数。

## 2. 头块字段

所有整数为小端序。偏移与长度单位为字节。

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 4 | `magic` | ASCII `MYPK` |
| 4 | 1 | `version` | 格式版本，当前为 `1` |
| 5 | 1 | `typeflag` | 类型码（ASCII，见 §3） |
| 6 | 1 | `flags` | bit0 = 1 表示 `btime` 有效；其余位必须为 0 |
| 7 | 1 | 保留 | 必须为 0 |
| 8 | 4 | `checksum` | CRC-32（IEEE 802.3，多项式 `0xEDB88320` 反射形式），覆盖头块与全部扩展块，计算时本字段按 0 处理 |
| 12 | 4 | `extBlocks` | 紧随其后的扩展块个数 |
| 16 | 4 | `pathLen` | 路径长度 |
| 20 | 4 | `linkLen` | 链接目标长度（软链接目标或硬链接指向的路径；其他类型为 0） |
| 24 | 4 | `mode` | 权限位与 setuid/setgid/sticky（只允许低 12 位，即 `0o7777`） |
| 28 | 4 | `uid` | 数字属主 |
| 32 | 4 | `gid` | 数字属组 |
| 36 | 4 | `devMajor` | 设备主号（仅字符/块设备） |
| 40 | 4 | `devMinor` | 设备次号（仅字符/块设备） |
| 44 | 4 | 保留 | 必须为 0 |
| 48 | 8 | `size` | 数据长度（有符号，必须 ≥ 0；只有普通文件可非 0） |
| 56 | 8 | `mtime.sec` | 修改时间，Unix 秒（有符号） |
| 64 | 8 | `atime.sec` | 访问时间 |
| 72 | 8 | `ctime.sec` | 状态变更时间（只用于展示与过滤，还原时无法设置） |
| 80 | 8 | `btime.sec` | 创建时间（`flags` bit0 为 0 时必须为 0） |
| 88 | 4 | `mtime.nsec` | 纳秒部分，必须 < 10⁹ |
| 92 | 4 | `atime.nsec` | 同上 |
| 96 | 4 | `ctime.nsec` | 同上 |
| 100 | 4 | `btime.nsec` | 同上 |
| 104 | 408 | 名字区 | 路径（`pathLen` 字节）紧接链接目标（`linkLen` 字节），剩余字节必须为 0 |

**名字区与扩展块**：路径与链接目标拼接后的总长 `n = pathLen + linkLen`。`n ≤ 408` 时全部内联；否则前 408 字节内联，其余依次写入 `extBlocks = ⌈(n − 408) / 512⌉` 个扩展块，最后一块的剩余字节为 0。`pathLen`、`linkLen` 各自不超过 65536（`MaxNameLen`），`extBlocks` 必须与上式一致。

## 3. 类型码

沿用课件的 tar 类型码，套接字为 MyPack 扩展：

| 码 | 类型 | 链接目标 | 数据 |
|---|---|---|---|
| `0` | 普通文件 | — | `size` 字节 |
| `1` | 硬链接 | 归档中**更早出现**的同一 inode 条目的路径 | 无（`size` = 0） |
| `2` | 软链接 | 链接内容，原样保存（可为绝对路径或悬空），非空 | 无 |
| `3` | 字符设备 | — | 无，设备号在 `devMajor/devMinor` |
| `4` | 块设备 | — | 无 |
| `5` | 目录 | — | 无 |
| `6` | 命名管道 FIFO | — | 无 |
| `7` | 套接字（扩展） | — | 无 |

与 `fsmeta.FileInfo` 的对应：类型码 `1` 读出为 `Type = TypeRegular` 且 `HardlinkTo` = 链接目标；`Dev/Ino/Nlink` 不写入归档，读出为 0。

## 4. 路径规则与安全校验

条目路径与硬链接目标都必须是"相对源目录、以 `/` 分隔"的规范路径：非空；不以 `/` 开头或结尾；不含空段、`.`、`..` 段；不含 NUL 字节。违反时 `Writer.WriteHeader` 与 `Reader.Next` 都返回 `pack.ErrUnsafePath`。

此外 `Reader` 记录已读出的软链接路径：若后续条目的路径或硬链接目标**以某个已出现的软链接为祖先**（例如先有软链接 `a → /etc`，再出现 `a/passwd`），同样返回 `ErrUnsafePath`。这阻止了"借软链接把文件写到还原目录之外"的经典 tar 攻击；还原端（engine）仍需自行保证不跟随软链接。

## 5. 读取校验（`Reader.Next`）

以下情况返回 `pack.ErrCorrupt`（`errors.Is` 可判断）：

- 魔数、版本、保留字节、`flags` 的未定义位不符；校验和不符；
- 未知类型码；`mode` 超出 `0o7777`；纳秒字段 ≥ 10⁹；`flags` 未标记 btime 却有非零 btime；
- `size` 为负，或非普通文件（含硬链接）的 `size` 非 0；
- `pathLen` 或 `linkLen` 超过 `MaxNameLen`；`extBlocks` 与名字长度不一致；名字区填充字节非 0；
- 软链接目标为空，或非链接类型的 `linkLen` 非 0；
- 头块、扩展块、数据块或结尾零块中途截断；只有一个零块而后跟非零块；没有结尾零块就到达流末尾。

出错后 `Reader` 保持该错误，之后的 `Next`/`Read` 都返回同一错误。

## 6. 示例

一个只含普通文件 `a.txt`（内容 `hello`）的归档共 2048 字节：

```
0x000  头块：MYPK 01 '0' 00 00 | checksum | extBlocks=0 | pathLen=5 | linkLen=0 | mode … size=5 …
       名字区："a.txt" + 403 个 0
0x200  数据块："hello" + 507 个 0
0x400  零块
0x600  零块
```

字节级样例锁定在 `backend/internal/pack/testdata/*.golden`，由 `go test ./internal/pack -update` 显式更新。
