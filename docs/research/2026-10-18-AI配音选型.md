# AI 配音选型调研（中文课程演示视频）

> 适用项目：DataBackup 演示视频（≤3 分钟中文技术旁白，v1.0.1）。
> 本文是 2026-10-18 的调研快照：版本号、许可与显存数字以当日仓库/模型卡为准，P1 部署时复验；证据分 A/B/C 级（见 §1），C 级只作量级参考。

- 调研对象：≤3 分钟中文技术讲解旁白；可提供 ≤100 秒本人声音样本；可租 8–24GB 显存 GPU（尽量不租几十 GB 的卡）
- 调研截止：**2026-10-18**（下文版本号/日期均为该日前后仓库与模型卡的实际状态）
- 结论口径：优先“零样本/少样本克隆 + 中文稳定 + 8–16GB 能跑 + 部署不折腾 + 许可可用于课程公开展示”

## 0. 结论速览（先看这一段）

| 档位 | 方案 | 一句话理由 |
|---|---|---|
| **第一选择** | **IndexTTS-2.5**（2026-08-10，0.8B） | 约 6GB 显存；`duration_factor` 0.5–2.0 直接控语速（对齐字幕的关键）；拼音/CMU 注音治多音字；`uv sync` 一条命令装完；长文自动分段、<10GB 显存自动低显存分段；许可允许课程公开展示 |
| **备选（质量优先）** | **GPT-SoVITS v2ProPlus / v4**（2025-06 / 2025-04） | **唯一能把 100 秒样本真正用满**（1 分钟 few-shot 微调）；MIT；推理 4.5–5GB、微调 8GB(LoRA)；RTF 0.014–0.028；中文前端（G2PW 多音字 + 数字归一化）最成熟 |
| **备选（零样本质量标杆）** | **CosyVoice3-0.5B-2512**（2025-12） | 官方 test-zh CER 1.21%（base）/ 0.81%（RL），论文口径 0.71%；CV3-Eval 中文相似度 80.0 为同表最高；Apache-2.0；约 5GB；内置数字/符号文本规范化；指令控语速/方言/情感。代价：装 pynini/sox 略折腾，参考音频硬上限 30s |
| **保底** | **F5-TTS v1 Base**（2025-03） | `pip install f5-tts` 一条命令即可跑，<4GB 显存，CLI 自带 0.3–2.0 语速；代价：参考音频被硬截到 ~12s、权重 CC-BY-NC、长文有吞字风险 |

> 如果第一诉求是“像本人 + 一次做好”，选 **GPT-SoVITS**（用满 100s 做微调）。
> 如果第一诉求是“今天下午就要出片、还要按字幕卡时长”，选 **IndexTTS-2.5**。
> 如果第一诉求是“中文最准、许可最干净”，选 **CosyVoice3**。

> **关于排序口径**：按第 6 节的加权表，GPT-SoVITS 4.49 略高于 IndexTTS-2.5 4.45；但 GPT-SoVITS 的分数依赖“花 30–60 分钟训练”。把训练计入“部署不折腾”后它降到 4.34，IndexTTS-2.5 反超。所以：**默认第一选择给 IndexTTS-2.5；愿意训练、想把 100s 用满的人选 GPT-SoVITS。** 两者不是“谁更好”，是“谁更适合本项目的时间预算”。

**一个必须先说清的事实**：主流零样本克隆模型的参考音频上限普遍是 **3–30 秒**，没有一个是“给 100 秒就更好”。100 秒样本的正确用法是：
1. 零样本路线：从 100 秒里挑 1 段最干净的 8–15 秒做 prompt，其余留作备用；
2. 少样本路线：把 100 秒切成 8–12 条 5–10 秒片段，做 GPT-SoVITS 的 1 分钟微调——这是唯一“用满 100 秒”的路线。

## 1. 调研方法与证据分级

- 证据等级 **A**：官方 README / 模型卡 / LICENSE / 官方文档中的明确数字或声明。
- 证据等级 **B**：官方代码里的硬约束（如 `assert <= 30s`、`_load_and_cut_audio(..., 15)`），或官方 issue 中维护者确认。
- 证据等级 **C**：社区实测/第三方文章，仅作量级参考，标注“社区”。
- 表中“—”表示官方未给出、也没找到可靠社区数据，不臆造。

> 注意：2026 年这一批项目的**仓库地址发生过迁移**：CosyVoice 已从 `FunAudioLLM/CosyVoice` 迁到 **`QwenAudio/CosyVoice`**（API 返回 full_name 为 QwenAudio/CosyVoice，2026-05 仍在更新）；Fish Speech 已从“1.4/1.5/1.6”版本叙事切换到 **S2-Pro / Drama 3** 型号叙事。二手教程里的老地址/老版本号要当心。

## 5. 逐项目详解

### 5.1 GPT-SoVITS（v2 / v3 / v4 / v2Pro / v2ProPlus / V5 分支）

- **最新状态**：正式 release 为 `20250606v2pro`、`20250422v4`、`20250228v3`；README 另有 **V5** 说明，但代码在分支 `cuda_graph_accel_v5`，属实验性。仓库 2026-10-08 仍在更新，63k stars。
- **中文自然度与稳定性**：中文社区的事实标准之一。前端最完整：PaddleSpeech `zh_normalization`（数字/单位/符号）+ `g2pW`/`G2PW` 多音字消歧 + `split-lang` 中英混排。v3/v4 主打“更少的重复与漏读”，v4 修掉了 v3 因非整数倍上采样导致的金属音并原生 48kHz。已知问题：v3 金属音（用 v4）；v1/v2 对干净录音的表现反而不如 v3/v4；16 系显卡训练会因半精度报错（自动强制 fp32）。
- **参考音频**：零样本 5s；**few-shot 1 分钟**（这就是 100s 样本的正确用法）。训练数据要求：切片 3–10s、去 BGM/混响、ASR 转写后**人工校对**（错字会直接教坏模型）。
- **显存**：推理 v2Pro 4.5GB(fp16)/7GB(fp32)，v4 5GB/8GB；训练 v3/v4 LoRA 8GB、全参 14GB；v1/v2 训练 10GB；v2Pro 12GB。
- **许可**：代码 MIT；HF 权重卡 `license: mit`。**课程演示/公开展示没有障碍**。
- **部署**：Windows 一键整合包（7z 解压 + `go-webui.bat`）；Linux `install.sh --device CU128 --source HF-Mirror`；官方 Docker（`xxxxrt666/gpt-sovits`，分 Lite/Full、CU126/CU128）。Python 3.10，torch 2.5.1/2.7.x。
- **速度/长文**：RTF 0.014（4090）、0.028（4060Ti）、0.526（M4 CPU）。3 分钟旁白约 3 秒生成完（不含加载）。长文按标点切片后逐段合成，稳定性好。
- **控制**：推理页有 speed 参数（约 0.5–2.0）；没有独立的情感参考音频，情绪基本由“参考音频本身”带出来（想要平静讲解，参考音频也要平静）；无“时长精确对齐”能力。
- **坑**：
  1. 流程长（切片→降噪→ASR→校对→格式化→训 GPT→训 SoVITS→推理），第一次约 30–60 分钟；
  2. v2Pro 必须先在数据准备阶段跑 `2-get-sv.py` 抽说话人向量，否则训练报 `5.1-sv/*.pt` 找不到；
  3. 整合包版本偏旧（`GPT-SoVITS-v3lora-20250228.7z`），要用 v4/v2Pro 需自己更新代码+下权重；
  4. 训练集音质差时 v3/v4 反而更差（官方明说），100s 干净样本没问题；
  5. 模型下载走 HF 需镜像（国内用 ModelScope/作者语雀链接）。
- **来源**：<https://github.com/RVC-Boss/GPT-SoVITS>；显存/RTF 表 <https://deepwiki.com/RVC-Boss/GPT-SoVITS/1.2-model-versions-and-evolution>；权重 <https://huggingface.co/lj1995/GPT-SoVITS>

### 5.2 IndexTTS-2.5（B 站 / IndexTeam，2026-08-10）

- **最新状态**：IndexTTS-2.5（2026-08-10）为最新；IndexTTS-2（2025-09-08）、IndexTTS-1.5（2025-05-14）仍在仓库内。0.8B，支持中/英/日/西/阿。
- **中文自然度与稳定性**：CV3-Eval 中文 WER 4.36 / SS 77.10（2.5-RL：3.93 / 77.92）；IndexTTS2 在 Seed-TTS Eval 中文 CER ≈1.03。工程上针对长文做了很多：`text_normalization=True`、按 `，。！？、；：` 分段、`max_text_tokens_per_segment=120`、段间 `interval_silence=200ms`、**显存 <10GB 自动开启低显存分段**（>40 字就切 40 字一段）。多音字用拼音标注：`他在银<行|XING2>里<行|HANG2>走了半天`。
- **参考音频**：代码 `_load_and_cut_audio(spk_audio_prompt, 15, ...)` **硬截断 15 秒**；官方示例 5–8s 最佳；过长只增加算力、还可能混入停顿。
- **显存**：模型卡 “roughly 6 GB for inference”（bf16）；官方支持 bf16（2.5）/fp16（2）。DeepSpeed 在 6GB 卡上不要开（社区 issue）。
- **许可**：bilibili Model Use License Agreement。免费使用、可公开展示；只有“月活 >1 亿 或 上年营收 >10 亿元”才需单独授权；禁止用其输出改进其他商用 AI 模型；高风险场景（医疗/自动驾驶/军事等）禁止。**课程演示完全没问题**。
- **部署**：`uv` 管理，Python 3.10–3.11，需要 CUDA Toolkit **12.8+**；`uv sync --all-extras` 一条命令；模型 `hf download IndexTeam/IndexTTS-2.5 --local-dir=checkpoints` 或 modelscope；Windows 可跑（去掉 `--all-extras` 避开 DeepSpeed）。辅助模型（w2v-bert-2.0、MaskGCT codec、CAMPPlus、BigVGAN）首次运行自动下到 `checkpoints/hf_cache/`。
- **速度/长文**：RTF 0.2065（4090，bf16，整体）；200 字长文 0.1997，几乎不随长度退化。3 分钟旁白 ≈ 40 秒生成。
- **控制**：`duration_factor` 0.5–2.0（>1 变慢、<1 变快）——**这是本表里最精确的语速控制**；还有 8 维情感向量、情感参考音频、`emo_alpha`、`use_emo_text`；拼音/CMU/日文假名注音。
- **坑**：
  1. 参考音频只能吃 15s，别指望 100s 全喂；
  2. `use_emo_text=True` 在 2.5 上必须 `use_qwen_emo=True`，否则 RuntimeError；
  3. 情感随机采样（`use_random`）会降低音色相似度；
  4. 辅助模型首次下载量大（w2v-bert + BigVGAN），国内要设 `HF_ENDPOINT=https://hf-mirror.com`；
  5. 输出 22.05kHz（不是 24/48k），对视频够用，但别再二次重采样多次。
- **来源**：<https://github.com/index-tts/index-tts>；<https://huggingface.co/IndexTeam/IndexTTS-2.5>；许可 <https://github.com/index-tts/index-tts/blob/main/LICENSE>

### 5.3 CosyVoice3-0.5B-2512（阿里 FunAudioLLM / 现 QwenAudio，2025-12）

- **最新状态**：Fun-CosyVoice3-0.5B-2512（2025-12）已开源 base + RL 权重与训练/推理脚本；CosyVoice2-0.5B（2024-12）仍可用；**CosyVoice3-1.5B 只在论文评测表里，未开源**。仓库已迁至 `QwenAudio/CosyVoice`。
- **中文自然度与稳定性**：官方评测 `test-zh` **CER 1.21%（base）/ 0.81%（RL）**；CosyVoice3 论文口径为 **0.71%**（Qwen3-TTS 的对比表引用该数）；在 IndexTTS 的 CV3-Eval 表里，CosyVoice3-0.5B 中文 WER 3.84、SS 80.01（同表 SS 最高）。官方强调 “Text Normalization: 数字、特殊符号、各种文本格式，无需传统前端”；“Pronunciation Inpainting: 中文拼音 / 英文 CMU 音素”。支持 9 语种 + 18 种中文方言/口音（粤、闽、川、东北、陕、沪、津、鲁…）。
- **参考音频**：代码 `assert speech.shape[1]/16000 <= 30`，**超过 30s 直接报错**；建议 3–10s，且 **prompt 内容会显著影响输出正确性**（官方 issue #816：同一文本换 prompt 会出现漏段/重复）。
- **显存**：社区部署实测 **~5.2GB**（3090）；vLLM 模式默认显存占比 0.2 ≈ 4.8GB。
- **许可**：**Apache-2.0**（代码 + 权重）。最干净的一档。
- **部署**：`git clone --recursive`（子模块 Matcha-TTS 必须成功）、conda py3.10、`pip install -r requirements.txt`、`apt install sox libsox-dev`、modelscope 下模型。ttsfrd 可选（装了文本规范化更好，但 wheel 只给 cp310 linux_x86_64）；不装则走 wetext。**pynini/WeTextProcessing 是主要安装痛点**（建议 `conda install -c conda-forge pynini`）。官方有 runtime Docker（fastapi/grpc）与 triton_trtllm。
- **速度/长文**：社区实测 RTF ≈0.45（生成 30s 约 67s）；但有 issue 报告某些云环境 RTF>2，根因是 0.5B 模型解码是串行小 kernel、与 GPU 算力脱钩（4090 利用率 <15%）。**换环境/换 torch 版本可能差 3–5 倍**，租卡前先跑 20 字基准。
- **控制**：`inference_instruct2` 支持“请用尽可能快地语速说一句话”“用四川话说”“<strong>”“[laughter]”“[breath]”等；语速是“指令式”而非数值式，**不如 IndexTTS 的 duration_factor 精确**。
- **坑**：
  1. 30s 硬上限；
  2. prompt 敏感（换 prompt 可能漏字/重复），一定要固定同一条 prompt；
  3. pynini/ttsfrd 安装折腾；
  4. 仓库迁移，老教程里的 `FunAudioLLM/CosyVoice` 地址可能 404 或指向旧代码；
  5. 1.5B 未开源，别按论文数字预期 0.5B 的表现。
- **来源**：<https://github.com/QwenAudio/CosyVoice>；<https://huggingface.co/FunAudioLLM/Fun-CosyVoice3-0.5B-2512>；30s 断言 <https://deepwiki.com/FunAudioLLM/CosyVoice/5.1.2-zero-shot-voice-cloning>；prompt 敏感 issue <https://github.com/FunAudioLLM/CosyVoice/issues/816>

### 5.4 Qwen3-TTS（阿里 Qwen，2026-01-22）

- **最新状态**：0.6B / 1.7B，12Hz 与 25Hz 两套 tokenizer；Base（克隆/微调）、CustomVoice（9 个预置音色 + 指令）、VoiceDesign（文字描述造音色）三种。Apache-2.0，13.8k stars。
- **中文自然度与稳定性**：CV3-Eval 中文 WER **3.27**（同表最好）/ SS 73.02；官方强调“对含噪文本鲁棒性明显提升”、10 语种、方言音色（北京/四川）。数字与中英混排处理是它的卖点之一。
- **参考音频**：Base 支持 **3 秒**快速克隆；FAQ 建议 3–5s，5–10s 更稳；`x_vector_only_mode=True` 可只取说话人向量（不需要转写，但相似度下降）。
- **显存**：官方最低 **8GB**（0.6B），推荐 16GB（1.7B）；FlashAttention-2 可选（Ampere+）。
- **许可**：**Apache-2.0**。
- **部署**：`pip install qwen-tts`（推荐 Python 3.12）；或 clone 后 `pip install -e .`；有 vLLM-Omni / DashScope API。
- **速度/长文**：第三方基准（faster-qwen3-tts，4090）：**基线 RTF 0.82× 实时（即比实时慢）**，CUDA Graphs 后 4.78× 实时；TTFA 850ms→174ms。官方称流式首包 97ms。**不加速的话 3 分钟旁白要跑 ~3.7 分钟**，这是它最大的短板。
- **控制**：CustomVoice/VoiceDesign 用自然语言指令控语速/情感；**Base 克隆模型的控制有限**（官方 FAQ 明说），但社区封装发现 ICL 模式下 `instruct` 可用（实验性）。
- **坑**：
  1. 基线推理慢，务必上 CUDA Graphs 或 vLLM；
  2. 官方 README 声称支持流式（含双轨流式、首包 97ms），但第三方封装指出官方仓库的流式路径有限、社区多靠 fork 补（`Qwen3-TTS-streaming`）；以你自己实测为准；
  3. ICL 克隆时参考音频最后一个音素会“渗”到开头，需在参考尾部补 0.5s 静音；
  4. 1.7B 在 8GB 卡上容易 OOM，需 fp16/减 batch。
- **来源**：<https://github.com/QwenLM/Qwen3-TTS>；<https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-Base>；FAQ <https://mintlify.wiki/QwenLM/Qwen3-TTS/resources/faq>

### 5.5 Fish Speech（S2-Pro / Drama 3；旧 1.4/1.5/1.5.1）

- **版本脉络**：v1.4.x（2024-09~11）→ v1.5.0（2024-12）/ v1.5.1（2025-05）→ **v2.0.0-beta = S2-Pro（4B，2026-03）** → **v3.0.0-beta = Drama 3（35B-A3B，2026-10-13）**。**没有 1.6**。
- **中文自然度与稳定性**：S2-Pro 官方 Seed-TTS 中文 WER **0.54%**（号称超过 Qwen3-TTS/MiniMax/Seed-TTS）；CV3-Eval 中文 3.62 / SS 67.79（相似度是短板）。Drama 3 主打长文、多角色、笑声/哭腔/耳语、局部编辑（把 “Wednesday” 改成 “Thursday”）。
- **参考音频**：官方“10–30 秒”即可复刻音色。
- **显存**：**官方推理文档明确建议 ≥24GB**（S2）；Drama 3 是 35B-A3B，消费卡无望。**这一条直接把它排除在 8–16GB 预算外**。
- **许可**：2026-10-13 起改为 **Fish Audio Community License v1.0**：研究/非商用免费；年营收 <50 万美元可商用；**Hosted Service 一律需单独授权**；**S2-Pro 权重仍适用 Fish Audio Research License（仅研究/非商用）**。旧 1.5.1 权重是 CC-BY-NC-SA-4.0。
- **部署**：官方 Docker（`fishaudio/fish-speech`），推荐 SGLang-Omni 或 vLLM-Omni 做高性能服务；Python 3.10–3.12。
- **速度/长文**：S2-Pro RTF 0.195（H200），首包 ~100ms；长文单遍流式输出，长对话/多角色是强项。
- **控制**：自然语言标签 `[whisper]`/`[angry]`/`[pause]`/`[laughing]`；多说话人 speaker id。
- **坑**：
  1. **显存**：S2 就要 24GB，Drama 3 更夸张；
  2. **许可变更频繁**：2026-10 刚换协议，S2-Pro 权重是非商用 Research License，商用要单独谈；
  3. 国内下载 HF 权重困难（Docker 镜像/镜像站）；
  4. 中文标点/标签语法敏感，标签写错会念出来；
  5. 旧教程（1.4/1.5）的 4GB 显存结论**不适用**于 S2/Drama 3。
- **来源**：<https://github.com/fishaudio/fish-speech>；<https://github.com/fishaudio/fish-speech/blob/main/LICENSE>；<https://huggingface.co/fishaudio/s2-pro>；推理显存建议 <https://speech.fish.audio/inference/>

### 5.6 F5-TTS（SWivid，v1 Base 2025-03）

- **最新状态**：v1 Base（2025-03-12）为最新；E2-TTS 同仓库。336M。
- **中文自然度与稳定性**：Seed-TTS 中文 WER 1.56（2024 年水平，已被 2025–26 模型超过）。**吞字/叠音是已知问题**：官方 issue #1179 记录 v1 在 batch 推理时短句吞字（缺 attention mask），社区分析认为根因是对齐不足，多次采样可缓解。**没有内置文本规范化**，数字/单位/符号需要自己先转成中文写法。
- **参考音频**：官方 infer 文档：**长参考音频会被裁到 ~12s**；建议 <12s，且**尾部留 ~1s 静音**，否则会在词中间截断。
- **显存**：不带 ASR <4GB；带 Whisper-v3-turbo 做 ref 转写约 6GB。
- **许可**：**代码 MIT，权重 CC-BY-NC-4.0（非商用）**。课程演示属非商用，可用；但若视频挂激励/接商单，就有风险。
- **部署**：`pip install f5-tts`；`f5-tts_infer-cli` / `f5-tts_infer-gradio`；官方 Docker `ghcr.io/swivid/f5-tts:main`；Python 3.10/3.11，torch 2.8+cu128。
- **速度/长文**：官方基准：PyTorch 0.147 RTF（L20）、TRT-LLM 0.04；单次生成总长（prompt+输出）**30s**，CLI/Gradio 会自动分块。
- **控制**：`--speed` 0.3–2.0（CLI 与 Gradio 都有），本质是时长缩放，极端值会损韵律。
- **坑**：
  1. 12s 参考硬截断，100s 样本用不上；
  2. batch 吞字（issue #1179）；
  3. 权重非商用；
  4. 英文标点后必须带空格才会被当句末切分；
  5. 无 TN，数字/英文缩写要先改写。
- **来源**：<https://github.com/SWivid/F5-TTS>；infer 说明 <https://github.com/SWivid/F5-TTS/blob/main/src/f5_tts/infer/README.md>；吞字 issue <https://github.com/SWivid/F5-TTS/issues/1179>；权重许可 <https://huggingface.co/SWivid/F5-TTS>

### 5.7 VoxCPM2（OpenBMB，2026-04）

- **最新状态**：VoxCPM2（2B，2026-04），30 语种 + 9 种中文方言，48kHz 输出，tokenizer-free 扩散自回归；前代 VoxCPM1.5（2025-12）、VoxCPM-0.5B（2025-09）。
- **中文自然度与稳定性**：官方技术报告中文 CER **0.92%**（很强）；中文 APS 85.2 与 Qwen3-TTS 并列第一。上下文感知韵律。
- **参考音频**：短参考即可；“Ultimate Cloning” 需要参考音频 + 精确转写（音频续写式克隆，细节最像）。
- **显存**：**~8GB**（官方性能表）。
- **许可**：**Apache-2.0**（代码+权重），明确“free for commercial use”。
- **部署**：`pip install voxcpm`（Python ≥3.10 <3.13，torch ≥2.5，CUDA ≥12）；也有 Nano-vLLM / vLLM-Omni 服务化。
- **速度/长文**：RTF 0.30（4090）/ 0.13（Nano-vLLM）。
- **控制**：括号风格指令 `(slightly faster, cheerful tone)`，可克隆同时调情绪/语速；Voice Design 可无参考造音色。
- **坑**：
  1. 2B 模型 8GB 是“贴边”，同时开别的进程容易 OOM；
  2. 风格指令是“自然语言”，不是数值参数；
  3. 48kHz 输出文件大，后期要转 48k/24bit 或 44.1k；
  4. 国内下载用 modelscope。
- **来源**：<https://github.com/OpenBMB/VoxCPM>；<https://huggingface.co/openbmb/VoxCPM2>；技术报告 <https://arxiv.org/abs/2606.06928>

### 5.8 OmniVoice（k2-fsa / 小米，2026-04）

- **最新状态**：0.8B，600+ 语种，diffusion LM 架构；2026-10-12 仍在更新，14.7k stars。
- **中文自然度与稳定性**：CV3-Eval 中文 WER 3.41 / SS 72.99。支持拼音声调纠音：`这批货物打ZHE2出售后他严重SHE2本了`，也支持 `[laughter]` 等非语义词。**数字需要 `normalize_text=True`**（依赖 WeTextProcessing/pynini）。
- **参考音频**：官方建议 **3–10 秒**；更长会变慢且可能降低克隆质量；跨语种会带参考语言口音。
- **显存**：0.8B fp16，约 4–6GB（社区）。
- **许可**：**Apache-2.0**。
- **部署**：`pip install omnivoice` 或 `uv sync`；torch 2.8；有 `omnivoice-demo` WebUI、CLI、batch 多卡。
- **速度/长文**：**RTF 0.025（40× 实时）**，本表最快之一；FlashInfer 还能再快 2–2.9×。
- **控制**：`speed`（倍率）、`duration`（秒数硬控，优先级高于 speed）、`instruct`（gender/age/pitch/accent/whisper）、拼音纠音。
- **坑**：
  1. 数字规范化是 opt-in，忘了就会读错；
  2. `pynini` 在 macOS 无 wheel，要 conda 装；
  3. 参考音频语言决定口音，中文旁白必须用中文参考；
  4. 社区生态还不如 GPT-SoVITS/IndexTTS 成熟（教程少）。
- **来源**：<https://github.com/k2-fsa/OmniVoice>；<https://huggingface.co/k2-fsa/OmniVoice>

### 5.9 GLM-TTS（智谱，2025-12-11）

- **最新状态**：1.5B，两阶段（LLM token + Flow Matching），多奖励 GRPO；2025-12-11 开源推理脚本与权重，RL 权重“coming soon”。
- **中文**：主打中文（英文混读），Seed-TTS 中文 CER 1.03（base）/ **0.89（RL）**，情感表达是卖点。
- **参考音频**：3–10s。
- **显存**：社区报 **10GB+**（官方未标注）。
- **许可**：**MIT**（HF 模型卡）。
- **部署**：Python 3.10–3.12，`pip install -r requirements.txt`；GRPO 训练依赖 s3prl/LaughterSegmentation，较重。
- **速度**：慢——社区实测 32kHz 模式 100 字约 45s、24kHz 约 22s，开 KV cache 再快 30%。
- **坑**：显存偏高、速度偏慢、RL 权重未放、主要为中文（多语种弱）。
- **来源**：<https://github.com/zai-org/GLM-TTS>；<https://huggingface.co/zai-org/GLM-TTS>

### 5.10 Spark-TTS（HKUST/SparkAudio，2025-03）

- **最新状态**：0.5B（Qwen2.5 底座），**仓库最后更新 2025-04-09，已停更**；训练代码/数据仍未放。
- **中文**：Seed-TTS 中文 WER 1.20，但长文稳定性差（社区反馈重复/漂移）。
- **参考音频**：prompt speech + 其转写，约 3–10s。
- **显存**：~4GB。
- **许可**：**代码 Apache-2.0，权重 CC-BY-NC-SA-4.0（非商用）**。
- **部署**：Python 3.12 + torch 2.5；Linux 为主（Windows 靠社区 issue #5）。
- **速度**：RTF 0.136（TRT-LLM，L20）。
- **控制**：可控生成模式可调 gender/pitch/rate，但那是“造虚拟说话人”，不是给克隆音频调语速。
- **坑**：停更、无训练代码、权重非商用、长文不稳。
- **来源**：<https://github.com/SparkAudio/Spark-TTS>；<https://huggingface.co/SparkAudio/Spark-TTS-0.5B>

### 5.11 MegaTTS3（字节，2025-03）

- **最新状态**：0.45B，中英双语 + 口音强度控制。
- **中文**：质量很高（字节系），但**工程上有一个致命卡点**。
- **参考音频**：官方要求 **<24s**，但——**WaveVAE 编码器权重未发布**，你必须提供 `A.wav` + `A.npy`（官方预抽取的声纹 latent），或把音频上传到官方 Google Drive 队列等他们回传。**这意味着你无法对自己的 100s 样本本地抽 latent**。
- **显存**：约 6GB（Ascend 实测 6.14GB）。
- **许可**：Apache-2.0。
- **部署**：Python 3.10 + torch 2.6 + gradio；有 Dockerfile。
- **速度**：10 步扩散，短句约 3.4s（≈RTF 0.5）。
- **控制**：`p_w` 口音强度（1.0 保留口音，增大趋标准音）；细粒度时长调节“coming soon”。
- **坑**：**latent 卡点**（最致命）、无训练代码、时长控制未上线。
- **来源**：<https://github.com/bytedance/MegaTTS3>

### 5.12 XTTS-v2（Coqui，2024）

- **中文**：支持 zh-cn，但中文自然度/数字读法明显落后 2025–26 模型（社区共识）。
- **参考音频**：6s。
- **显存**：2–4GB。
- **许可**：**Coqui Public Model License（CPML）——非商用**。
- **部署**：`pip install coqui-tts`，Python 3.9–3.11。
- **速度**：~0.3–0.5 RTF（社区）。
- **控制**：无原生语速参数；靠标点/文本。
- **坑**：非商用、停更、中文弱、24kHz。
- **来源**：<https://huggingface.co/coqui/XTTS-v2>；<https://github.com/idiap/coqui-ai-TTS>

### 5.13 OpenVoice V2（MyShell，2024-04）

## 6. 评分与推荐排序

### 6.1 评分口径（按本项目约束加权）

| 维度 | 权重 | 说明 |
|---|---|---|
| 中文自然度/稳定性（吞字、多音字、数字） | 30% | 技术旁白最怕读错 |
| 100s 样本适配 | 15% | 能否用上、用多少 |
| 显存（8–16GB 友好度） | 15% | 越省越好租 |
| 许可（课程公开展示） | 10% | 非商用/商用条款 |
| 部署不折腾 | 15% | 装依赖、下模型、跑通时间 |
| 速度 + 长文稳定性 | 10% | 3 分钟旁白 |
| 语速/韵律控制 | 5% | 对齐字幕 |

### 6.2 评分结果（1–5 分，主观但可复核）

**分档**：
- 第一梯队（≥4.4）：GPT-SoVITS / IndexTTS-2.5 / OmniVoice / CosyVoice3 —— 都能满足“8–16GB + 中文技术旁白”，差别在“训练成本 / 语速控制 / 生态成熟度”。
- 第二梯队（4.0–4.4）：VoxCPM2 / Qwen3-TTS —— 单看指标很强，但一个 8GB 贴边、一个基线推理慢。

> **为什么 OmniVoice 4.44 却不是第一选择**：它的中文证据主要来自 CV3-Eval（WER 3.41 好，但 SS 72.99 是头部里最低），且中文技术旁白的社区案例/教程远少于 GPT-SoVITS 与 IndexTTS；数字规范化还要额外开 `normalize_text=True`。**它是“极简保底”里最快、最省事的一条**（RTF 0.025、pip 一条命令、Apache-2.0），但把“中文旁白一次过”押在它身上证据不足。
>
> **为什么 GPT-SoVITS 4.49 排第一档却不是默认第一**：它的高分来自“用满 100s + 速度 + MIT”，代价是 30–60 分钟训练流程。把训练成本计入“部署不折腾”（部署分 3.0→2.0）后加权变为 **4.34**，低于 IndexTTS-2.5 的 **4.45**。所以：**赶时间选 IndexTTS-2.5，愿意训练选 GPT-SoVITS。**

### 6.3 最终推荐

**第一选择：IndexTTS-2.5**
- 理由：6GB 显存就能跑（8GB 卡余量充足）；`uv sync` 一条命令装完，Windows 也能跑；`duration_factor` 是唯一“数值化语速”，做 3 分钟卡字幕的视频这是决定性优势；拼音注音解决技术名词多音字；长文自动分段 + 低显存自动分段，3 分钟一次跑完不用手写分句；bilibili 许可对课程展示完全够用。
- 什么时候不该选它：你需要“尽可能像本人”（它只用 15s 参考），或必须 48kHz。

**备选 A（质量/相似度优先，愿意训练）：GPT-SoVITS v2ProPlus 或 v4**
- 理由：把 100 秒切成 1 分钟训练集做 few-shot，音色相似度和稳定性是这批里最稳的；MIT；4.5GB 推理、8GB LoRA 训练；RTF 0.014，改一版文案几秒出结果；中文前端（多音字/数字）最成熟。
- 代价：WebUI 六步流程 + 30–60 分钟；v4 48kHz 但要求录音干净（本项目的 100s 干净样本正好）。

**备选 B（中文最准、许可最干净）：CosyVoice3-0.5B-2512**
- 理由：官方 test-zh CER 1.21%（base）/ 0.81%（RL），论文口径 0.71%；CV3-Eval 中文 SS 80.0 为同表最高；Apache-2.0；5.2GB；内置数字/符号规范化；指令控语速/方言。
- 代价：pynini/sox/子模块安装折腾；参考音频 30s 硬上限；语速是指令式不精确。

**保底：F5-TTS v1 Base**
- 理由：`pip install f5-tts` 一条命令，<4GB 显存，CLI 稳定，0.3–2.0 语速；任何机器 10 分钟内能出声。
- 代价：12s 参考截断、CC-BY-NC 权重、长文吞字 → 只当“前两个装不起来”的兜底。

> 另一条“极简保底”：**VoxCPM2**（`pip install voxcpm`，8GB，Apache-2.0，中文 CER 0.92）或 **OmniVoice**（`pip install omnivoice`，RTF 0.025，Apache-2.0）。两者都比 F5 更现代，但生态/教程少一些。

**批量合成 3 分钟旁白（分句 + 固定 prompt + 拼静音 + 响度归一）**

```python
# 另存为 scripts/video/tts_batch_indextts.py（新任务创建；build/ 已 gitignore，临时脚本也可放 build/）
import re, soundfile as sf, numpy as np
from indextts.infer_v2_5 import IndexTTS2

tts = IndexTTS2(cfg_path="checkpoints/config.yaml", model_dir="checkpoints", use_bf16=True)

REF = "voice_ref_10s.wav"          # 从 100s 样本里挑的最干净 8-12s
SPEED = 1.0                        # >1 变慢，<1 变快；按字幕时长微调
SR = 22050

text = open("narration.txt", encoding="utf-8").read().strip()
# 按句末标点切；保留标点，避免语气断裂
sentences = [s for s in re.split(r'(?<=[。！？；])', text) if s.strip()]

wavs = []
for i, s in enumerate(sentences):
    out = f"seg_{i:03d}.wav"
    tts.infer(spk_audio_prompt=REF, text=s, lang="ZH",
              output_path=out, duration_factor=SPEED,
              text_normalization=True, verbose=True)
    wavs.append(out)

# 拼接：段间 250ms 静音
sil = np.zeros(int(0.25 * SR), dtype=np.float32)
buf = []
for w in wavs:
    a, sr = sf.read(w, dtype="float32")
    if sr != SR:                    # 兜底：万一模型改了采样率
        import librosa; a = librosa.resample(a, orig_sr=sr, target_sr=SR)
    buf += [a, sil]
final = np.concatenate(buf[:-1])
sf.write("narration_raw.wav", final, SR)
print("duration(s) =", len(final) / SR)
```

```bash
# 响度归一 + 转 48k/24bit（B 站/剪映都吃）
ffmpeg -y -i narration_raw.wav -af "loudnorm=I=-16:TP=-1.5:LRA=11" \
       -ar 48000 -c:a pcm_s24le narration_final.wav
```

## 8. 声音样本准备清单

### 8.1 录制规格

| 项 | 要求 | 原因 |
|---|---|---|
| 采样率/位深 | 录音 48kHz/24bit，**保留原始母带**；给模型时再重采样到 16k/22.05k/24k | 多次重采样会糊 |
| 声道 | 单声道（mono） | 立体声会被下混，可能相位抵消 |
| 总时长 | **60–100 秒**（GPT-SoVITS 微调 60–90s 足够） | 超过 100s 收益递减 |
| 分段 | 8–14 条，每条 **4–8 秒**，句间停 **0.3–0.5s** | 切训练集/挑 prompt 都方便 |
| 电平 | 峰值 **-6 ~ -3 dBFS**，整体 **-18 ~ -16 LUFS** | 不削波，模型不吃爆音 |
| 底噪 | 本底 < **-55 dBFS**，SNR > **30dB** | 底噪会被克隆进去 |
| 环境 | 小房间、挂毯/衣柜前、关空调/风扇；**不要混响** | 混响是克隆音质的头号杀手 |
| 麦克风 | USB 电容麦/领夹麦均可，离嘴 15–20cm，加防喷罩 | 防喷麦、防口水音 |
| 格式 | WAV（PCM），文件名英文无空格 | 部分脚本对中文路径不友好 |

### 8.2 文本覆盖（照读脚本必须包含）

1. **数字**：`2026 年`、`3.5%`、`1,024`、`128GB`、`第 3 章`、`2 的 10 次方`
2. **英文/缩写**：`AES`、`JSON`、`CLI`、`Huffman`、`SHA-256`、`Linux`、`API`（观察模型是逐字母读还是拼读）
3. **多音字**：行（xíng/háng）、长（cháng/zhǎng）、重（chóng/zhòng）、都（dōu/dū）、着（zhe/zháo）、得（de/dé/děi）、还（hái/huán）、差（chā/chà）
4. **标点与语气**：陈述句、疑问句、感叹句、顿号并列、破折号、括号补充
5. **技术术语**：备份、还原、元数据、归档、压缩、加密、校验和、增量、快照
6. **长句**：一条 25–35 字的完整长句（测试断句与气息）
7. **轻声/儿化**：可选，按讲课习惯

> 让录音文本**就是**后续要合成风格的文本（技术讲解、中性、稍慢），不要用朗读腔/播音腔，否则克隆出来也是播音腔。

### 8.3 后期处理（越少越好）

```bash
# 1) 裁掉首尾静音，但保留 0.3s 尾部
ffmpeg -i raw.wav -af "silenceremove=start_periods=1:start_silence=0.1:start_threshold=-50dB" trimmed.wav

# 2) 轻降噪（可选；宁可留一点底噪也不要过度处理）
deepFilter trimmed.wav -o denoised/            # DeepFilterNet3 的命令行；或 RNNoise
# 3) 统一电平
ffmpeg -i denoised/trimmed.wav -af "loudnorm=I=-18:TP=-3:LRA=9" -ar 48000 norm.wav
# 4) 按句切分（Audacity 手工切最稳；或 ffmpeg silencedetect 辅助）
ffmpeg -i norm.wav -af silencedetect=noise=-40dB:d=0.3 -f null -
```

**不要做**：压缩器、EQ、混响、降噪拉满、变速、变调——这些都会让克隆“不像本人”。

## 9. 质量验收方法

### 9.1 ASR 回译 + CER/WER（客观）

目标：**中文 CER ≤ 2%**；任一句 **>5% 判不合格，重生成**。
推荐 ASR：FunASR `paraformer-zh`（中文最准）或 `faster-whisper large-v3`（多语混排）。

```python
# 另存为 scripts/video/qa_cer.py（新任务创建）
import re
from funasr import AutoModel
from jiwer import cer as jiwer_cer

asr = AutoModel(model="paraformer-zh", vad_model="fsmn-vad", punc_model="ct-punc")

def norm(s):
    # 只保留汉字/字母/数字，标点与空白全部去掉（避免中英文标点差异干扰）
    s = re.sub(r"[^\u4e00-\u9fffA-Za-z0-9]", "", s)
    return s.lower()

def cer(ref, hyp):
    return jiwer_cer(norm(ref), norm(hyp))

pairs = []  # [(ref_text, wav_path), ...] 由分句脚本产出（seg_000.wav 对应第 0 句）
results = []
for ref, wav in pairs:
    hyp = asr.generate(input=wav)[0]["text"]
    c = cer(ref, hyp)
    results.append(c)
    flag = "OK  " if c <= 0.02 else ("WARN" if c <= 0.05 else "FAIL")
    print(f"{flag} CER={c:.3%}  {wav}\n  REF={ref}\n  HYP={hyp}")

print("MEAN CER =", f"{sum(results)/len(results):.3%}" if results else "no data")
```

**判读**：
- CER 高但 HYP 语义对 → 多音字/数字读法问题，改文本（用拼音注音或中文数字写法）；
- CER 高且 HYP 少字 → 吞字，换 seed / 缩短单段 / 换模型；
- CER 高且 HYP 多字/重复 → 幻觉重复，降低 `max_text_tokens_per_segment` 或换 seed。

### 9.2 人工试听（主观，逐项打勾）

| # | 检查项 | 合格标准 |
|---|---|---|
| 1 | 吞字/漏字 | 对照文稿逐字听，0 处 |
| 2 | 多音字 | 行/长/重/都/着/得 全部正确 |
| 3 | 数字 | “2026”“3.5%”“128GB”读法符合中文习惯 |
| 4 | 英文缩写 | 逐字母或拼读，前后一致（不能这句 AES 逐字母、下句拼读） |
| 5 | 术语 | Huffman/元数据/校验和 清晰无粘连 |
| 6 | 句尾语调 | 陈述句降调，疑问句升调，不“念经” |
| 7 | 呼吸/气口 | 长句中间有自然换气，不憋气 |
| 8 | 杂音 | 无爆音、口水音、电流声、机械感 |
| 9 | 段落衔接 | 段间静音自然，无“重启感” |
| 10 | 音色一致性 | 开头 30s 与结尾 30s 盲听像同一人 |
| 11 | 整体语速 | 240–300 字/分钟（技术讲解偏慢） |
| 12 | 响度 | -16 LUFS，真峰值 ≤ -1.5 dBTP |

建议找 3–5 位同学做盲听（A/B 两版），5 分制，均分 <3.5 就重做。

### 9.3 与字幕时长对齐

1. 先定字幕：把旁白稿按句写成 SRT，得到每句目标时长 `T_target`；
2. 合成后测每句实际时长 `T_gen`（`ffprobe`/`soundfile`）；
3. 偏差 `|T_gen-T_target|/T_target > 8%` 时：
   - IndexTTS-2.5：调 `duration_factor`（>1 变慢）；每句单独调，别全局调；
   - CosyVoice3：在 instruct 里写“请稍快/稍慢地说这句话”；
   - GPT-SoVITS：推理页 `speed` 微调（0.9–1.1 之间，超出会损音质）；
4. **不要**用 `atempo` 超过 ±5% 硬拉（会有金属感/共振峰漂移）；宁可改文案（加/删 2–3 个字）；
5. 总时长验收：`ffprobe -show_entries format=duration`，**≤180s**，留 5–8s 余量给片头片尾；
6. 最后整体听一遍“画面切换点是否落在句间静音上”，必要时在剪辑里微调画面而不是拉音频。

```bash
# 每段时长统计
for f in seg_*.wav; do printf "%s\t" "$f"; ffprobe -v error -show_entries format=duration -of csv=p=0 "$f"; done
```

## 12. 附：3 分钟旁白工程参数速查

- 中文技术讲解语速：**240–300 字/分钟** → 180 秒约 **720–900 字**；建议先写 800 字，留 10% 余量。
- 单句长度：**15–35 字**（超过 40 字模型容易气息不足/吞字）。
- 段间静音：**200–300ms**；章节之间 400–600ms。
- 采样率：IndexTTS 22.05k / CosyVoice 24k / GPT-SoVITS 32k(v2Pro) 或 48k(v4) / VoxCPM 48k → 统一在后期重采样到 **48kHz/24bit**。
- 响度：**-16 LUFS**（B 站/YouTube 通用），真峰值 **-1.5 dBTP**。
- 备份：`narration_final.wav` + 每句 `seg_*.wav` + `narration.txt` + `narration.srt` 一起归档，方便改一句重生成一句。
