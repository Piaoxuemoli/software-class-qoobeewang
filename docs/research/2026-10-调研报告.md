# 调研报告：开源方案、测试、仓库构建、agent 辅助开发与客户端实现

> 时间：2026-10-15。目的：在开工前对照优秀开源项目，校正本项目的方案。每节先写结论（本项目采纳什么），再写依据。

## 0. 结论速览

| 方面 | 采纳 | 主要参考 |
|---|---|---|
| 后端结构 | 保持 `cmd/` + `internal/`，不建 `pkg/`；一个包一个概念 | restic |
| 前后端关系 | 后端二进制随客户端分发，客户端只是"外壳 + 界面"，后端可独立运行 | Kopia / KopiaUI |
| 测试夹具 | 声明式目录树 `TestDir{...}` + `CreateTree` / `EnsureTree`，比较器覆盖正确性五要素 | restic `internal/archiver/testing.go` |
| CLI 端到端测试 | 引入 `testscript`（txtar 脚本，Go 官方 `go` 命令同款测试方式），**仅测试依赖** | rogpeppe/go-internal |
| 格式与解码器 | golden 文件 + Go 原生 fuzz | Go 标准库 `archive/tar` 的测试方式 |
| agent 指令 | 根 `AGENTS.md` 当目录（约 100 行指针）+ `backend/AGENTS.md`、`client/AGENTS.md` 分区补充 | agents.md 标准、OpenAI Codex 指令合并规则 |
| agent 流程 | 规格 → 计划 → 任务 → 实现 → 核对（spec-driven），每个任务带"可运行的检查"，并行用 worktree | GitHub spec-kit、Claude Code 最佳实践 |
| 客户端底座 | 保留现有 electron-vite + electron-builder；接入 Tailwind v4 + shadcn/ui（官方 electron-vite 集成方式） | shadcn/shadcn-electron-app |
| 窗口外框 | `frame: false` + 自绘标题栏与窗口按钮（不依赖原生/WCO） | guasam/electron-react-app、Cherry Studio；Electron issue #52576 |
| 视觉 | Grok 式纯黑单色：`#000` 画布、白色为唯一强调、细线边框、胶囊按钮、Inter/Geist | grok.com 设计拆解 |
| 动效组件 | React Bits（经 shadcn registry 拷入源码），只用于少数关键时刻，可一键关闭 | reactbits.dev |

## 1. 备份类开源项目

### 1.1 restic（Go）

- 结构：`cmd/restic` 单一入口 + 全部逻辑在 `internal/`（archiver、restorer、fs、crypto、filter、repository/pack…），明确"这是工具不是库"。本项目包划分与之一致，无需调整。
- 测试：
  - `internal/test` 提供 `OK/Equals/Assert` 等极简断言和临时目录环境；
  - `internal/archiver/testing.go` 用 `TestDir{"foo": TestFile{Content: "foo"}, "link": TestSymlink{Target: ...}, "hard": TestHardlink{...}}` 声明目录树，`TestCreateFiles` 生成、`TestEnsureFiles` 校验——**直接借鉴为 `internal/testutil`**，并扩展 FIFO、设备、权限、属主、时间字段；
  - 各命令有 `*_integration_test.go`，用统一 `testEnvironment` 管理临时目录与仓库初始化；
  - 后端有一套共享的验收测试，所有实现必须通过（本项目对应：`pack.Reader/Writer`、`huffman`、`crypto` 各自的往返与向量测试）。
- 来源：<https://panos-zamos.github.io/go/docs/projects/restic/structure/>、<https://deepwiki.com/restic/restic/9.3-testing-infrastructure>、<https://github.com/restic/restic/blob/987caba4/internal/archiver/testing.go>

### 1.2 Kopia（Go）与 KopiaUI（Electron）

- KopiaUI 只是 Electron 外壳：启动内置的 `kopia` 二进制并连接它；二进制作为资源打进安装包。与本项目"Electron 调后端 CLI、后端二进制放 `resources/bin`"完全同构，说明方向可行。
- 教训：Kopia 团队后来认为 Electron 体积大、npm 供应链风险高，计划改成 Go 托盘程序。对本项目的启示：
  - npm 依赖要少而精，版本精确锁定、发布满 7 天（已在规范中）；
  - 业务逻辑必须全在 Go 后端，客户端可替换——这也正好满足课程"后台不能用脚本语言"。
- 来源：<https://github.com/kopia/kopia/blob/master/BUILD.md>、<https://kopia.discourse.group/t/big-changes-coming-to-kopia-ui/820>

## 2. 测试方案

| 手段 | 用途 | 采纳方式 |
|---|---|---|
| 声明式目录树夹具（restic） | 往返测试的输入与期望 | `internal/testutil`：`Tree`/`File`/`Dir`/`Symlink`/`Hardlink`/`FIFO`/`Device`，`CreateTree`、`AssertTreeEqual`（五要素） |
| testscript（Go 团队测试 `go` 命令的方式） | CLI 黑盒测试：一个 `.txtar` 文件里写命令、期望输出与输入文件；支持 `-update` 更新期望 | `backend/cmd/databackup/testdata/script/*.txtar`；**仅作为测试依赖**，生产代码依旧零依赖 |
| golden 文件 | MyPack 头记录、容器头的字节级格式锁定 | `testdata/*.golden`，`-update` 显式更新 |
| Go 原生 fuzz | `pack.Reader`、Huffman 解码、容器头解析面对任意输入不 panic | `FuzzXxx`，CI 中短时运行，本地可长跑 |
| 标准库对照（differential） | 手写 AES/SHA-256/HMAC/PBKDF2 与标准库输出逐字节比对 | 标准库只出现在 `_test.go`（`check-imports` 已保证） |
| 测试向量 | FIPS-197、NIST SHA-256、RFC 4231、PBKDF2-HMAC-SHA256 | 写进 `testdata/vectors/` |
| Playwright 截图对比 | 客户端界面回归（agent 改 UI 时有客观判据） | 在 Docker 开发镜像中运行，字体固定，`toHaveScreenshot` |

来源：<https://github.com/rogpeppe/go-internal>（testscript 说明：从 Go 团队内部 `cmd/go/internal/script` 抽出，支持 stdout/stderr 断言、自动更新 golden、与 `go test` 和覆盖率集成）。

## 3. 仓库构建与 agent 辅助开发

### 3.1 AGENTS.md 标准

- AGENTS.md 是面向 agent 的 README，已成为跨工具的开放格式（Codex、Copilot、Cursor 等均读取）。
- Codex 从仓库根目录向当前目录逐级合并 `AGENTS.md`，越近越优先，总长默认上限 32 KiB → **根文件保持精简（目录 + 硬约束），分区规则下沉到 `backend/AGENTS.md`、`client/AGENTS.md`**。
- 推荐写法："AGENTS.md as table of contents"——约 100 行指针，知识放 `docs/`。
- 来源：<https://github.com/agentsmd/agents.md>、<https://developers.openai.com/codex/guides/agents-md>、<https://www.agentpatterns.ai/standards/agents-md/>

### 3.2 规格驱动（GitHub spec-kit）

- 流程：constitution（项目原则，一次）→ specify（做什么、为什么）→ plan（技术方案）→ tasks（依赖有序的任务）→ implement → converge（对照规格核对，补剩余工作）。
- 本项目映射：constitution = `AGENTS.md` + `docs/conventions/`；specify = 需求说明书 FR/UC；plan = `docs/plans/<任务ID>.md`；tasks = `docs/roadmap.md`；converge = PR 模板里的"验收标准逐条核对 + 文档同步"。不引入 spec-kit 工具本身，只借流程。
- 来源：<https://github.com/github/spec-kit>

### 3.3 Claude Code / 通用 agent 实践

- 最重要的一条：**给 agent 一个能自己运行的检查**（测试、构建、lint、截图对比），否则"看起来完成"就是唯一信号。→ 每个 roadmap 任务的验收标准必须可由命令判定；UI 任务以 Playwright 截图/交互测试为判据。
- 并行：3~5 个会话各用独立 git worktree；worktree 是新检出，需要各自初始化环境。→ 本项目 Docker 方式天然隔离（每个 worktree 跑 `bash scripts/docker.sh check`；node_modules 卷需按 worktree 区分，见 roadmap §并行规则）。
- 来源：<https://code.claude.com/docs/en/best-practices>、<https://code.claude.com/docs/en/worktrees>

## 4. 客户端实现

### 4.1 底座模板对比

| 项目 | 构建 | 特点 | 结论 |
|---|---|---|---|
| shadcn/shadcn-electron-app | electron-vite | shadcn 作者给出的 electron-vite 接入步骤（components.json、zinc 基色、CSS 变量） | **采用其接入方式**，与现有脚手架同构，迁移成本最低 |
| guasam/electron-react-app | electron-vite + electron-builder | 自绘窗口外框/标题栏/菜单、Zod 校验的类型化 IPC、sandbox | 借鉴标题栏与窗口控制 IPC 的写法，不整体替换 |
| LuanRoger/electron-shadcn | Electron Forge | React 19、Tailwind 4、shadcn、Geist、`titleBarStyle: hidden`、Playwright | 打包链不同（Forge），只参考样式与结构 |
| CherryHQ/cherry-studio | electron-vite | 成熟的开源 Electron 客户端：React 19 + shadcn + Tailwind、自绘标题栏与窗口控制、类型化 IPC 边界 | 作为交互与工程组织的参照 |

来源：<https://github.com/shadcn/shadcn-electron-app>、<https://github.com/guasam/electron-react-app>、<https://github.com/LuanRoger/electron-shadcn>、<https://github.com/CherryHQ/cherry-studio/blob/main/docs/references/architecture-overview.md>

### 4.2 无边框窗口

- Electron 官方做法：`titleBarStyle: 'hidden'` + `titleBarOverlay`（Windows/Linux 显示原生按钮）。
- 风险：Electron 44 alpha 起出现"Linux 上 WCO 按钮不显示"的问题（electron/electron#52576，修复 PR #52577），本项目锁定的 Electron 44.7.0 处于受影响版本线。
- **结论**：`frame: false`，标题栏与最小化/最大化/关闭按钮全部用 React 自绘，经 IPC 调用 `BrowserWindow` 方法；拖拽区用 `-webkit-app-region: drag`，按钮区 `no-drag`。这样在 Linux（演示环境 WSLg）、Windows 上外观一致，也最能去掉"原生感"。另设 `backgroundColor: '#000000'` + `show: false` / `ready-to-show`，避免白屏闪烁。
- 来源：<https://github.com/electron/electron/blob/main/docs/tutorial/custom-title-bar.md>、<https://github.com/electron/electron/issues/52576>

### 4.3 Grok 视觉语言

- grok.com：大面积近黑/近白留白、一个居中的主任务、圆角描边面板、胶囊按钮、极克制的阴影；主文字 `#FCFCFC`，次要 `#9E9E9E`；暖橙 `#FF6B35` 只作极少量点缀。
- Grok iOS：纯 `#000000` 画布，界面几乎单色——**白色本身就是强调色**（发送按钮、激活态胶囊都是黑白反转），Inter 字体，字重 400/600/700。
- 来源：<https://fudge.design/share/grok.com-design>、<https://github.com/Meliwat/awesome-ios-design-md/blob/main/design-md/misc/grok/DESIGN.md>
- 落地见 `docs/client/ui-design.md`。

### 4.4 React Bits

- 免费开源的动效组件库，每个组件提供 TS + Tailwind 版本，可用 `npx shadcn@latest add https://reactbits.dev/r/<组件>-TS-TW` 拷入源码；依赖因组件而异（motion、gsap、ogl、three）。
- 许可：MIT + Commons Clause——允许在应用中使用（含商用），禁止单独出售/再分发组件本身。本项目作为应用的一部分使用，合规；在 `client/src/components/reactbits/` 保留来源注释。
- 选用原则：只在"开始备份、进度、完成、空状态"等少数时刻使用；WebGL 背景类默认关闭（WSLg 可能无 GPU 加速），提供"减少动效"开关并尊重 `prefers-reduced-motion`。
- 来源：<https://reactbits.dev/get-started/introduction>、<https://reactbits.dev/llms.txt>
