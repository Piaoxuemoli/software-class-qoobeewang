DataBackup UML 图集

课程交付物附图 · 组长：王科瑾 · 由 docs/deliverables/diagrams/*.puml 重绘导出（同一模型，未使用 StarUML 软件）

图 1 用例图

覆盖 UC-01 ~ UC-07：备份、过滤、还原、口令（加密时 extend）、列表、删除、设置仓库，以及 dry-run 预览。

图 2 类图（后端）

engine、walk、filter、pack、huffman、container、repo 的公开类型与依赖关系；与 M1-3 冻结的签名一致。

图 3 顶层构件图

客户端（renderer / preload / main）与后端 CLI 的进程边界，以及 JSON Lines 协议所在位置。

图 4 后端构件图

CLI → engine → pack / huffman / container / repo 的调用方向，无数据库。

图 5 客户端构件图

renderer 经 contextBridge 暴露的白名单 API 调用 main，main 再 spawn 后端。

图 6 顺序图：备份

scan → pack → compress → encrypt → 原子发布。进度和结果由 CLI 写到 stdout 的 JSONL，main 解析后再交给界面。

图 7 顺序图：加密备份还原

先整文件校验再落盘；错误口令返回 E_AUTH（退出码 3），客户端重试。

图 8 顺序图：dry-run 预览

不写仓库，只遍历并套用过滤条件，把文件数/字节数返回界面。

图 9 顺序图：列表与删除

list 与 info 都只读容器头尾；损坏文件以 corrupt=true 标记。删除是长按约 1.2 秒，不是确认对话框。

图 10 备份任务状态图

jobStore 的 9 个状态都在图上。加密还原在 Running 前进入 AwaitingPassword；口令类错误（E_AUTH / E_PASSWORD_REQUIRED，3 次以内）回到该状态，连续 3 次口令错误或关闭对话框回到 Ready。
